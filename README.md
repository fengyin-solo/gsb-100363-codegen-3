# 森林防火巡护管理系统

面向森林火险监测、巡护任务调度、防火设施维护与应急响应指挥的林区防火管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `forest-fire-patrol:entries` 这一项，或调用 `resetModule(模块)`。

## 解除预警复评（firereview）

值班员在「预警复评」页按**监测区域 + 火险等级**定位监测点发起复评，系统结合**监测时间、
风力等级、现场记录**给出「可解除 / 维持 / 升级」建议，复评单走 待复评 → 已生效 → 已归档。
业务规则集中在 `frontend/src/api/review-service.ts`，既定口径如下：

- **裁决口径**：系统建议与人工结论冲突时就高不就低（升级 > 维持 > 可解除）。
- **补值口径**：风力等级缺测或不可解析时按升级阈值补值（最不利情形），并在评估备注标注。
- **优先级**：现场记录危险信号（明火/冒烟等）> 风力升级阈值 > 监测时间超期封顶 >
  首次有效观测封顶 > 可解除判定 > 维持兜底。
- **首次有效观测**：缺历史读数（此前无复评单）的监测点，建议封顶「维持」，升级条件除外。
- **超期判定**：监测时间距复评时间超过阈值天数（默认 3 天）即不具备解除条件。
- **检查站同步**：复评生效后，检查站提醒以最新已生效复评单的裁决结论为准——升级则
  非关闭站点转「升级检查」，可解除则转「正常检查」，维持不动；临时关闭站点不打扰。
  原观测记录（firewatch）保持原样，复评不改写监测点数据。
- **规则重算**：调整统一阈值后，未归档复评单全部按新阈值重算并再同步检查站；已归档单冻结。
- **幂等**：同一监测点编号 + 同一监测时间只允许一份复评单，重复提交返回原单。
- **原子性**：复评生效、规则重算涉及复评单与检查站两个模块的写入，任一失败一起退回
  （`local-store.ts` 的 `runAtomic` 快照回滚）。
